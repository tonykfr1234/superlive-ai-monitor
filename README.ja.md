新しいアプリアイコンと高画質録画：元のキャプチャ解像度で H.264 CRF 18 を保存。Telegram は同じ高画質の元動画を優先送信し、サイズ制限を超えた場合だけ一時コピーを圧縮して送信成功後に削除します。

SuperLive AI Monitor は、Windows の MuMu 上で表示する SuperLive のライブ映像に、人物・車両検出とイベント録画を追加します。YOLO が選択した多角形内の人物や車両を検出し、活動に応じて録画を開始。完成した動画を Telegram に送信します。カメラの RTSP アドレスは不要です。

SuperLive および MuMu の提供元とは関係のない、非公式のコミュニティプロジェクトです。**12 言語への対応はドキュメントのみです。アプリのプレビュー画面は現在、繁体字中国語で表示されます。**

**2026-10-21 更新：** 人物または車両（乗用車、オートバイ、バス、トラック）の動きで録画を開始します。120 秒の送信停止と 120～300 秒の録画規則は維持し、日次 CSV は例外です。Telegram は人物・車種・実際のナンバーを区別し、未確認は未確認と表示します。全画面と重なり合う領域を走査し、OCR プロセスの異常から自動復旧します。最大 7 日分の履歴はホイール、スクロールバー、PageUp／PageDown で確認でき、元動画の再認識、検出なし、未確認、失敗も記録します。

初期表示では、ローカルの照合リストに最大2文字の編集距離で一致した確認済み結果を展開し、その他の記録は折りたたみます。動画のファイル名をクリックすると、Windows エクスプローラーで元動画が選択されます。

認識状態・画質・一括処理の進捗は下部の操作ボタン付近に残ります。ナンバー認識を有効にすると、一致した記録を右側に常時表示し、台湾の日付ごとに件数を付けて新しい順にまとめます。狭いウィンドウでは一覧を映像の下に配置し、映像の縦横比を保ちます。「其他紀錄」で下のその他の記録を展開して移動でき、折りたたむと一致した記録に戻ります。

<a id="quick-start"></a>
## はじめに

1. MuMu と SuperLive をインストールし、ログインして対象カメラのライブ映像を開きます。Windows のユーザーセッションもログイン状態にしてください。
2. リポジトリをクローンまたはダウンロードし、`installer\INSTALL_FROM_REPO.bat` または上記の PowerShell コマンドを実行します。
3. `installer\SET_TELEGRAM.bat` で自分の Bot と Chat をローカルに設定します。認証情報はリポジトリに含まれません。
4. ライブ映像を開いたまま `installer\VERIFY_ALL.bat` でインストール状態を確認します。この確認だけでは Telegram への動画送信成功は保証されません。
5. `%USERPROFILE%\Downloads\SuperLive_AI\Start_AI_Monitor.bat` で開始し、同じフォルダーの `Stop_AI_Monitor.bat` で停止します。

**既存環境の更新：** `installer\UPDATE_FROM_REPO.bat` を実行してください。バックアップを作成して実行中のプログラムを停止し、ローカルの Telegram・検出範囲・保存先の設定を維持します。更新後は停止状態のままなので、映像を確認して手動で再開してください。Windows の自動起動、スケジュールタスク、サービスは作成しません。

<a id="workflow"></a>
## 動作の流れ

1. 範囲内に新しい人物や車両が現れるか、検出済みの対象が再び動くと、録画を開始します。各動画の最初の **120 秒間は、Telegram への新たな自動送信を停止**します。
2. 録画中も人物・車両の検出を続けます。開始から **120 秒以上、300 秒未満**で動きを検出すると、現在の動画を直ちに終了して次の録画を開始します。新しい動画も最初の 120 秒間は送信を停止します。
3. 通常の録画は **最短 2 分、最長 5 分**です。人物や車両の動きがない状態が連続で 120 秒続いた場合にも終了します。
4. 完成した動画を、永続化された Telegram のバックグラウンド送信キューに追加します。開始時の Telegram 写真通知はありません。
5. 検出を続け、再度の動きや新しい人物や車両の到着を待ちます。同じ人が静止したままでは、終了直後に再録画しません。

起動後に初めて見つかった人物や車両も新しい活動として扱います。対象がない状態も、すべての対象が静止している状態も「動きなし」で、動きを検出するたびに無活動時間を数え直します。範囲の編集中や、有効な映像・検出結果が得られない間は観測区間をリセットし、復旧後に有効な観測時間を数え直します。

Telegram は完成した動画、確認済みのナンバープレート、日次 CSV を自動送信します。新しい動画の送信停止期間中は、過去の動画や再試行もすべて待機します。録画の切り替えが続くと、待機中の動画の送信も遅れます。停止するのは新しい送信処理の開始です。すでに送信中の通信は取り消せないため、その動画が停止期間中に届く場合はあります。

<a id="controls"></a>
## 多角形の操作

| 操作 | 動作 |
| --- | --- |
| R／範囲選択 | 多角形の作成を開始 |
| 左クリック | 境界に沿った順序で頂点を追加 |
| 右クリック／Backspace | 最後の頂点を削除 |
| Enter／保存 | 有効な多角形を閉じて保存 |
| Esc／キャンセル | 変更前の範囲を維持 |
| C／画面全体 | 範囲の制限を解除 |

異なる頂点を 3 個以上選び、辺が交差しないようにしてください。ショートカットはプレビューにフォーカスがあるときに使えます。範囲は切り出したカメラ映像に対する相対座標で保存され、映像内の時刻やチャンネル表示は残ります。

<a id="faq"></a>
## よくある質問

**動画は必ず 5 分ですか？** いいえ。通常は 2～5 分です。開始から 120 秒以上、300 秒未満で動きを検出すると、その動画を終了して次の録画を開始します。連続 120 秒の無活動でも終了します。手動停止や障害時は 120 秒未満の部分動画になることがあり、ローカルに保存されます。送信停止期間が終わるまではアップロードを開始しません。

**動きはどう判定しますか？** 人物・車両の検出枠の位置・大きさの変化で判定します。小さな揺れは無視し、ゆっくりした移動は蓄積します。ただし、枠が変わらない手足の動きは検出できない場合があります。遮蔽、カメラの動き、検出誤差も影響するため、姿勢推定や物理的なモーションセンサーの代わりにはなりません。

**多角形の内側だけを録画しますか？** いいえ。多角形は人物・車両によるイベント開始の判定に使い、動画には切り出したカメラ映像全体を保存します。

**仮想マシンで GPU を使えますか？** CPU 推論に対応しています。VMware のグラフィックスアクセラレーションは CUDA とは異なります。初期設定では 60 秒ごとにディスクを確認し、ドライブ全体の使用率が 80% に達すると、78% まで古い終了済み動画を削除します。録画中・送信待ちのファイルは保護します。

## Daily CSV · 23:00 Asia/Taipei

毎日 23:00（台湾時間）に当日 00:00 以上、23:00 未満のトリガー CSV を送信し、動画と同じフォルダーに保存します。日次 CSV は録画の静穏期間の例外です。23:00 以降のイベントは含めず、深夜の補足送信も行いません。0 件でも報告し、通信失敗や再起動後は再試行します。
