# ADB 高解析度擷取與車牌辨識

## 目前規則（2026-10-27）

持續分析攝影機的新影格，未錄影時也辨識；至少三張不同時間、位置連續的畫面確認車牌後立即通知，繼續辨識其他車輛。同一實際讀值正規化後三分鐘內只通知一次，重啟仍保留冷卻；不同車牌各自計時。車牌通知不受錄影前兩分鐘靜默限制，影片另外依錄影時間先後傳送並保留影片靜默規則。不掃描歷史影片。七天本機記憶仍只使用獨立錄影片段的清楚證據，不憑空補字，也不是重訓模型。

歷史影片掃描預設停用，介面不再顯示舊批次進度。以下文件涉及離線重掃的部分僅供日後明確選用；命令未加 `--allow-history` 不會開啟影片、載入補辨識模型或發送通知。已存在的影片與紀錄保留。

本機辨識記憶存於 `runtime/plate_learning/memory.json`，只累積七天內新片段的清楚讀值及同畫面混淆候選。同一片段只計一票，至少三段獨立影片支持後才輔助排序目前影像實際讀出的近似候選；不補造缺字、不用名單比對冒充 OCR，受記憶影響的推測也不再當作學習答案。這不是重新訓練神經網路權重；反覆出現的系統性 OCR 錯誤仍可能需要人工修正。詳細門檻及重設方式見[使用說明](使用說明.txt)。

SuperLive AI 可從 MuMu／逍遙模擬器視窗擷取影像；逍遙另可使用 ADB，直接讀取 Android 畫面。人物／車輛偵測與車牌辨識使用不同模型，GUI 會顯示模型名稱、人物／車輛數與最多七天的辨識時間、OCR 讀值及比對結果。

## 目前使用的模型

| 用途 | 模型 | 說明 |
| --- | --- | --- |
| 人物與車輛偵測 | YOLO11n（`yolo11n.pt`） | 人物、汽車、機車、巴士、卡車；依多邊形內的移動觸發錄影 |
| 車牌位置 | YOLOv9-t 384 license plate | 車牌專用偵測模型 |
| 車牌字元 | FastPlateOCR CCT-S v2 global | 將車牌裁切影像讀成文字 |

[FastALPR](https://github.com/ankandrew/fast-alpr) 將車牌偵測與 [FastPlateOCR](https://github.com/ankandrew/fast-plate-ocr) 組合使用。單純換成更新的一般物件 YOLO，並不會自動具備讀車牌文字的能力。

截至 2026-10-21，[Ultralytics 官方已發布 YOLO26](https://docs.ultralytics.com/models/yolo26/)，並列出尚未發布的 YOLO27 預覽。本專案保留 YOLO11n；是否更換應比較同一監視器影片上的漏偵測、誤報、CPU／GPU 負載與延遲，不能只依版本號判斷。

## 啟用 MuMu／逍遙 ADB 擷取

新電腦執行專案最外層 `INSTALL.bat`，安裝完成會自動開啟設定視窗。既有安裝執行安裝目錄的 `Settings.bat`。視窗會尋找 MuMu／逍遙 ADB 並連接本機模擬器，未連線每 15 秒重試；多台時請選定一台，找不到程式時可手動選取 adb.exe。需要先開啟模擬器、啟用 ADB 並登入 SuperLive 即時畫面。

新安裝預設 `source: adb`、`auto_detect: true`；更新保留現有設定。已選定的裝置固定使用，不會切換到其他裝置。不掃描區域網路，也不重啟共用 ADB server。已停用 auto_detect 的舊設定仍使用原本指定路徑與裝置。

執行期間連線或畫質確認失敗仍會持續重試；最高畫質確認並關閉選單後才開始偵測。ADB 串流中斷會重建擷取，明確選擇 ADB 時不會退回擷取被遮住的桌面。切換模擬器後重新確認多邊形。完整安裝及車牌校正方式見 [新電腦一鍵安裝](INSTALL.zh-TW.md)。

ADB 讀取 Android 原生畫面，Windows 視窗大小不再將來源限制為 620 × 348；預覽仍等比例顯示。實際細節取決於攝影機串流、App 畫質與 Android 顯示解析度，放大或提高傳輸位元率無法補回來源不存在的細節。

串流以 H.264、16 Mbps、Android 畫面尺寸擷取；目前支援至 3840 × 2160。Android `screenrecord` 每段最多三分鐘，因此背景串流會重新連接，交接可能有短暫缺口。擷取、解碼與推論仍有延遲，GUI 的影格新鮮度檢查會拒絕過期畫面。

## 在開始偵測前確認最高畫質

`ensure_highest: true` 會在 ADB 擷取準備階段打開 SuperLive 的畫質選單、選擇「最高」、驗證選取狀態並關閉選單，完成後才進入正常偵測。已選最高時會直接驗證，避免重複點選。若無法確認或選單未關閉，會顯示等待重試；保持 SuperLive 即時畫面開啟，程式會自動再確認。正常運作時不會每小時打開選單，三分鐘串流換段也不會重新打開選單。

此操作依 SuperLive Android 介面的控制項辨識；App 改版或其他監視器 App 可能需要重新適配。視窗擷取模式請自行在 App 選好最高畫質。

畫質的選取顏色使用一秒 ADB 影片影格確認，避免部分逍遙版本的單張截圖漏掉浮動選單；這段驗證資料只在記憶體中處理，不儲存為監視影片，也不傳送 Telegram。介面結構每次重新取得，無法取得時不使用舊的選單座標。

## 畫面停止更新時重開指定頻道

ADB 連線仍在線、影格仍持續送達，不代表監視器畫面真的有更新。啟用 `recovery` 後，程式另外觀察攝影機內容是否變化，包含畫面內的時間戳記；這與「沒有人或車輛移動」是不同判斷，不使用錄影的兩分鐘無移動規則來重開 App。

在本機 `config/capture_config.json` 加入以下設定，將 `device_name` 改成 SuperLive 裝置清單中完整且唯一的名稱：

```json
"recovery": {
  "enabled": true,
  "device_name": "你的裝置名稱",
  "channel": 1,
  "stale_seconds": 60,
  "retry_seconds": 30,
  "frame_roi": null
}
```

`frame_roi` 留空時使用預設的影像觀察範圍；也可設定 `[left, top, right, bottom]`（0～1 相對座標），只觀察固定顯示攝影機時間戳記的範圍，避開 App 選單或系統時鐘。這不是人物／車輛錄影的多邊形。

這是既有 JSON 物件中的一個欄位，其他 ADB、來源與畫質設定需保留。公開範本預設關閉此功能且裝置名稱留空；安裝更新不覆寫既有的本機裝置設定。

來源畫面持續停止更新達設定時間後，程式會再以獨立的 ADB 取像確認，區分擷取管線卡住與 App 內的攝影機畫面卡住。確認需要重開時，先暫停提供影像，重新開啟 SuperLive，選回指定裝置與頻道並重新確認畫質。原有 8 秒無影格的擷取重試仍保留；持續無法取像達門檻且 ADB 裝置在線時，也會進入 App 復原。恢復期間不把裝置清單、登入頁或選單當作監視影像。指定名稱／頻道無法確認時會顯示狀態並等待重試，不自行選擇其他攝影機；停止監控後不再重開 App。

判斷需要一段觀察時間，重開與重新連線也會造成影像缺口；影像內容與時間戳記必須能提供更新證據。登入過期、裝置離線或 App 介面改版，可能需要先在 SuperLive 處理。這個功能目前用於 ADB 擷取，視窗擷取模式不會自動操作模擬器。

## 指定車牌與兩碼容錯

在本機 `config/plate_allowlist.json` 填入要比對的車牌字串陣列。公開安裝範本為 `[]`，不包含任何使用者車牌。修改後程式會重新讀取名單；舊的未確認樣本不會拿來湊成新名單的事件。

比對會忽略大小寫、空白與分隔符號。容許最多兩次字元編輯：數字或英文的替換、漏字或多字都計算一次；不是每種類型各容許兩次。少於四個可讀字元不會判定通過。若多個名單項目與讀值同樣接近，會顯示待確認，不自行選一個。

畫面與紀錄保留 **OCR 實際讀值**，並另外顯示 **比對到的名單項目與差異碼數**。容錯命中不代表所有字元均已正確辨識。每筆確認需要八秒內至少三個不同影格的讀值，並檢查偵測／OCR 信心；同一車牌六十秒內不重複建立事件。

小車牌會另外嘗試將裁切放大三倍再辨識，依 OCR 信心選取候選，保留原始與放大後的兩種讀值作為證據。同一影格的兩次 OCR 只算一次確認樣本，不會依目標名單改寫 OCR 答案。

## 全畫面掃描、程序恢復與狀態顯示

每次車牌辨識先掃描完整畫面；較大畫面另掃描四個互相重疊、寬高各約原畫面 60% 的區塊，減少整張影像縮小時遠處車牌細節流失。結果會轉回完整畫面的座標並去除重複，不會把同一影格的多次讀值算成多影格確認。掃描不以人物或車輛先被 YOLO 偵測為前提，也不受人物／車輛的錄影多邊形限制。

車牌模型在獨立程序運作，影格準備與恢復檢查不阻塞預覽操作。程序退出、啟動逾時或心跳過期時，會清理舊程序並逐步延長等待後重新啟動；模型或相依套件持續不可用時仍會顯示原因並重試。恢復期間人物／車輛偵測可繼續進行，沒有 OCR 結果就保持未確認。

辨識狀態、擷取來源及解析度、最高畫質、最近掃描與批次進度集中在底部按鈕區。啟用車牌辨識時，右側常駐顯示符合本機名單（最多兩碼容錯）的已確認結果，依台灣日期分組並列出每日筆數，日期及紀錄都由新到舊排列；窄視窗改放影像下方，監視影像始終保持等比例，不將文字蓋在影像上。其他車牌、未辨識、候選未確認及失敗結果收折在下方；點擊底部「其他紀錄」會展開並跳到該區，再次收起後回到符合紀錄。紀錄時間、實際讀值、名單結果與影片檔名依寬度換行；可使用滑鼠滾輪、點擊或拖曳捲軸、PageUp／PageDown 翻頁，Home／End 到最上方或最下方。

重疊區塊與放大 OCR 增加取樣機會，無法還原來源不存在的字元。反光、動態模糊、遮擋及過小的車牌仍可能無法確認；車輛偵測成功不等於已讀到車牌。

## 安裝與本機資料

人物、車輛與 GUI 使用 `.venv`；車牌模型使用獨立的 `.plate-venv`，由 `requirements-plates.txt` 安裝。請勿將 `opencv-python-headless` 安裝進 GUI 的 `.venv`，以免預覽視窗失效。首次載入車牌模型需下載模型檔；套件或模型不可用時，車牌欄會顯示狀態，人物與車輛偵測仍可運作。

即時確認的車牌事件儲存在 `runtime/plate_events`；供 GUI 查看的最多七天歷史位於 `runtime/plate_history/*.json`，原片批次辨識進度位於 `runtime/plate_replay`。這些執行資料、ADB 裝置設定及車牌名單都屬於本機資料，Git 已排除追蹤；公開版只有空白名單與通用設定範本。

Telegram 通知附台灣時間與實際讀值。完全符合本機指定車牌時加上 🚨 ⭐，容錯結果使用 🔎 ⚠️「可能符合」；不顯示未符合名單或車牌未確認。影片說明保留時間與所屬片段的車牌，不以名單號碼取代 OCR。

人物或支援的車輛在多邊形內移動皆可觸發錄影；沒有讀到車牌不會阻止車輛移動觸發。車牌事件本身不啟動錄影。正常片段 120–300 秒、前 120 秒不切段、滿 120 秒後移動換片及連續 120 秒無移動停止等規則維持不變。

影片與影片重試遵守每段錄影前兩分鐘靜默；即時車牌與每日 23:00 CSV 例外。同一讀值依實際成功傳送時間冷卻 180 秒；不同讀值不共用冷卻。CSV 彙整當天 00:00（含）至 23:00（不含），與影片一起保存。

## 七天紀錄與原片批次辨識

歷史最多保留七天，包含已確認車牌及每段完成錄影的未辨識結果。沒有讀到車牌、只有候選但未達確認門檻、解碼或辨識失敗，分別顯示「未辨識到車牌」、「有候選但未確認」、「辨識失敗」，並附時間與影片檔名；不會省略失敗影片或填入猜測號碼。

預設只展開符合本機名單且差異不超過兩碼的已確認結果。其他車牌、未辨識及失敗結果收在「其他辨識紀錄」；點擊可展開或收起，不會刪除紀錄。名單為空時顯示所有已確認車牌。原始 OCR 與容錯結果仍分開顯示。

點擊藍色影片檔名（換行後的每行皆可點）會開啟 Windows 檔案總管並選取該原始 MP4，不會播放影片。若檔案已搬移、刪除或有多個同名候選，畫面會顯示找不到或無法確定位置；不任意開啟其他檔案。完整路徑與回溯索引只保留在本機，不加入 Telegram 說明或公開儲存庫。

既有錄影的批次補辨識更新本機歷史，不大量補發舊事件的 Telegram 通知；所有補辨識明確標示來源，確認時間使用原始片段對應時間。合成示範影片的結果也只能作為流程測試，不視為真實監視器辨識證據。七天期限適用於辨識歷史，影片仍依既有儲存及磁碟清理規則管理。

### Telegram 傳送順序

影片由早到晚傳送，舊片重試會擋住後面的影片。車牌使用獨立執行緒，確認後立即通知，不等待影片完成或上傳。因此可能先收到車牌，稍後才收到較早開始的影片；影片之間仍按錄影時間排序。

影片說明中的車牌是該片內容摘要，不取代即時通知，也不改變車牌的三分鐘冷卻。新版只即時傳送啟用後的新事件，不重新推播歷史辨識。網路錯誤會重試；每日 CSV 仍獨立傳送。

上傳以小塊串流傳送原本的高畫質 MP4，保留 Content-Length 與 TLS 憑證驗證。網路失敗仍可能延後整個佇列；此更新不能重新排列 Telegram 已經送出的歷史訊息。
