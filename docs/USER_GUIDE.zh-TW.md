# 使用指南（繁體中文）

## 1. 準備與安裝

Windows 監控帳號必須保持登入。安裝並開啟 MuMu 或逍遙，在模擬器內開啟 SuperLive 攝影機即時畫面並啟用 ADB。完整下載與解壓縮 Repo 後，雙擊最外層 **`INSTALL.bat`**。

安裝器會準備 Python 3.12、監控及獨立車牌 OCR 環境，再開啟本機設定視窗，自動偵測 ADB。多台模擬器需選定一台，尚未連線時會重試。操作與前置需求見 [新電腦一鍵安裝](INSTALL.zh-TW.md)。

程式部署到 `%USERPROFILE%\Downloads\SuperLive_AI`，新安裝影片預設存入其中的 `recordings`；升級保留原位置。已有安裝使用 `installer\UPDATE_FROM_REPO.bat`，更新先備份、停止程式並保留本機設定，完成後再手動啟動。

## 2. 設定 Telegram 與車牌

安裝後設定視窗可填寫 Bot Token、數字 Chat ID、特別標示名單及車牌校正。之後執行安裝目錄的 **`Settings.bat`** 可再修改。先在 Telegram 開啟自己的 Bot 並按 Start；「驗證 Bot Token」只驗證 Bot，不傳送訊息，不會自動選取收件者。兩欄留空則停用 Telegram。

設定只寫入安裝目錄 `config`，不能 Commit／Push。校正保留原始辨識證據；已確認的拼法僅排序 OCR 實際讀出的高信心候選，人工別名只對完整誤讀值套用。詳見 [車牌校正與隱私](INSTALL.zh-TW.md#車牌放大圖與校正)。

`installer\VERIFY_ALL.bat` 可檢查部署檔案、Python 及編碼器，但不能取代實際確認 ADB 預覽與 Telegram 接收狀態。

## 3. 啟停與多邊形區域

使用安裝目錄的 `Start_AI_Monitor.bat` 與 `Stop_AI_Monitor.bat`。Start 啟動兩個 Watchdog；Stop 要求結束並儲存目前片段，手動停止可能留下未滿 120 秒的影片，不會補畫面湊長度。待傳影片於下次啟動繼續處理，但仍需遵守靜默期限。

預覽介面目前使用繁體中文，右下區塊集中 R、C、Q、儲存、取消及其他按鈕；左下並排顯示最近車輛與對應的車牌放大圖。多語言 README 是文件翻譯，不是介面語言設定。設定步驟：

1. 點 R／設定區域。
2. 沿區域邊緣依序用左鍵點選至少三個不同頂點。
3. 需要修正時，右鍵或 Backspace 移除最後一點。
4. Enter／儲存自動封閉並儲存多邊形；邊線不可交叉，區域必須有面積。
5. Esc／取消保留原區域；C／全畫面清除區域限制；Q 停止監控。

快捷鍵需要預覽視窗取得焦點。支援凹形多邊形；人員辨識框與區域必須有實際面積重疊才計入，只碰邊線不計入。未設定區域時使用完整攝影機內容。

頂點以攝影機內容區的相對座標存於 `config\notification_policy.json`，重新啟動仍保留，也支援舊矩形。若裁切後無法安全轉換舊區域，程式會等待重新選取或明確點選 C／全畫面。切換攝影機或畫面配置後請再次確認。

## 4. 移動、錄影與通知

閒置時首次看到人員或偵測到重新移動，就開始影片，產生本機 Windows 通知與快照，不自動傳送 Telegram 起始照片。錄影期間持續偵測。

正常影片為 **120–300 秒**。前 120 秒偵測到移動，只重設無移動計時，不自動分段；滿 120 秒後、達 300 秒上限前，偵測到移動就立即結束目前影片並開始新片，每段新片都有自己的 120 秒靜默期。

無人與靜止都算無移動；連續 120 秒無人移動後會結束並持續等待，等再次移動或新人進入才重新錄影，靜止者不會立即再次觸發。選取區域、擷取失敗或無有效偵測結果時屬未知，會重設無移動觀察區間。單段最低片長與連續無移動時間是兩個不同條件。

**Telegram 自動傳送完成影片及每日 CSV 報表。** 目前影片前 120 秒不啟動新的 Telegram 傳送，舊片與重試也一併延後；持續換片可能讓待傳佇列繼續等待。靜默期開始前已送出的網路請求仍可能在期間內抵達，無法撤回。主動執行 `SET_TELEGRAM.bat` 的設定測試訊息仍可使用。

移動判斷使用人員框的位置或大小變化，不是姿態辨識。輕微抖動會過濾，慢速位移會累積；攝影機移動、遮擋或漏偵測仍可能影響結果，請用實際場景驗收。

## 5. 影片與儲存

影片保留裁切後的完整攝影機內容，不含底部操作列，也不裁成多邊形大小。預設 10 FPS、`C:\SuperLive_Recordings`，正常每段 120–300 秒。完成後在背景轉成 Telegram 可播放的 H.264 MP4，等待適用的靜默期結束再傳送；失敗會保留佇列，重啟後繼續重試。

手動停止或擷取故障可能留下未滿 120 秒的本機片段，不會補畫面偽造片長，也不會在該片靜默期限前自動傳送。如果新片仍在靜默期，舊短片也會一起等待。

錄影磁碟總使用率達 80% 開始刪除符合條件的最舊已關閉影片，降至 78% 停止；目前錄影與受待傳工作保護的影片不會刪除。詳見[錄影設計](RECORDING.md)。

## 6. 常見問題

- **區域快捷鍵沒反應：** 先點預覽視窗取得焦點，或直接使用底部按鈕。
- **人還站在畫面裡卻沒有重新錄影：** 需再次移動或新人進入，這是預期行為。
- **兩分鐘好像延後：** 移動、未知擷取狀態或選取區域會重設觀察區間。
- **影片已完成卻還在等待：** 目前影片前 120 秒會暫緩所有新 Telegram 傳送，連續換片會延長等待。
- **人一移動就換新片：** 舊片已滿 120 秒、未達 300 秒上限時，這是預期行為。
- **畫面全黑或找不到 MuMu：** 保持 Windows 登入與正確即時畫面開啟。
- **VM 裡推論慢：** 沒有真正 NVIDIA CUDA 時使用 CPU 屬正常；VMware 3D 加速不提供 CUDA 運算。
- **Telegram 失敗：** 檢查本機設定與網路；靜默期規則允許傳送時，待傳影片會重試。
- **Recorder 重啟：** 查看安裝目錄的 `logs\Stage5C`，不要把紀錄或影片提交到 Git。


### 2026-10-19 · MuMu / MEmu（逍遙模擬器）

支援 MuMu 與逍遙模擬器。新安裝預設 ADB 自動偵測，模擬器被遮住仍可擷取；選定的裝置斷線後自動重連。切換來源後重新設定多邊形。四區預覽維持比例，空白以柔化背景補齊。

MuMu and MEmu are supported through automatically discovered ADB. An obscured emulator can still be captured; reselect the polygon after switching sources. See INSTALL.en.md for setup and DASHBOARD.en.md for the four-panel layout.


2026-10-21 更新：ADB 與車牌辨識
目前人物模型為 YOLO11n，GUI 會顯示名稱。車牌另用 YOLO 車牌模型與 CCT OCR，顯示最近五筆台灣時間及讀取文字；以本機名單比對，忽略大小寫及連字號，最多容錯兩碼（漏字、多字、錯字合計）。原始讀值與比對結果分開呈現，須多影格確認。
ADB 模式直接擷取 Android 內部解析度，不受桌面遮擋或視窗尺寸影響；開始監控前確認 SuperLive「最高」，收起選單再啟動偵測，不每小時操作。無法確認時暫停等待，不會誤報最高畫質。
ADB 仍有編碼與傳輸延遲；每180秒串流重連可能短暫中斷。實際畫質仍受攝影機串流限制。Windows 桌面擷取模式則仍需畫面保持可見。
Telegram 改成直接傳送高畫質原片；僅超過傳送大小限制時才製作暫時壓縮副本，成功後移除副本。車牌訊息與影片說明附時間及實際辨識值，同樣遵守前兩分鐘靜默；每日23:00 CSV仍是例外。
設定與詳情請見 docs/PLATE_AND_ADB.zh-TW.md（GitHub 專案）；實際車牌名單、帳密、攝影機影像與訓練素材不公開上傳。
